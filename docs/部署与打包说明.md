# 部署与打包说明

本文记录本地开发、Windows 发布包、云服务器部署和 LLM 配置注意事项，避免后续忘记关键启动参数。

## 本地开发启动

后端默认启动：

```powershell
python backend/run.py
```

当前默认行为：

- 监听地址：`127.0.0.1`
- 端口：`8000`
- 热重载：关闭

如果需要局域网访问或开发热重载，使用：

```powershell
$env:APP_HOST="0.0.0.0"
$env:APP_PORT="8000"
$env:APP_RELOAD="true"
python backend/run.py
```

前端开发仍按原方式启动：

```powershell
cd frontend
npm run dev
```

## LLM 配置

后端 `.env` 需要包含：

```env
LLM_API_KEY=你的模型服务密钥
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-max
```

LLM 请求路径：

```text
POST /api/ai/analyze
```

曾经出现过“请求异常、好像没有正常调用 LLM”的问题，原因是后端先导入 AI router，再加载 `.env`，导致 LLM 客户端初始化时拿不到 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`。现在已调整为先加载 `.env`，并在调用时创建 LLM 客户端。

## Windows 发布包

构建命令：

```powershell
scripts\build-windows-release.bat
```

脚本会执行：

- 构建前端 `frontend/dist`
- 使用 `.venv-release` 准备 PyInstaller 环境
- 生成后端 exe
- 把发布包复制到 DailyList 目录

默认发布目录：

```text
E:\迎风聚智\组内项目\water_plant\DailyList\20260612-模型接入、场景优化\water-plant-windows
```

发布包运行方式：

```text
双击 start-water-plant.bat
```

默认访问地址：

```text
http://127.0.0.1:8000
```

发布包内 `.env` 会被后端 exe 读取。如需换模型、换 API Key，修改发布包目录里的 `.env`。

## 云服务器部署

推荐 Docker / Docker Compose 部署。当前 `docker-compose.yml` 中：

- 前端映射：`80:80`
- 后端映射：`8000:8000`

别人访问：

```text
http://服务器公网IP/
```

如果不用 Docker，而是在服务器上直接运行后端，必须监听 `0.0.0.0`：

```bash
APP_HOST=0.0.0.0 APP_PORT=8000 python backend/run.py
```

同时确认云服务器安全组和系统防火墙放行对应端口。常见选择：

- 对外只开放 `80`，由前端/Nginx 代理后端
- 临时调试时开放 `8000`

## 不需要上传云服务器或提交 Git 的文件

这些是本地构建环境或打包产物，不需要上传云服务器，也不应该提交：

```text
.venv-release/
backend/build/
backend/dist/
frontend/dist/
water-plant-windows/
*.zip
*.7z
```

这些文件建议保留在仓库中，因为它们是可重复构建发布包的脚本或配置：

```text
backend/water_plant.spec
scripts/build-windows-release.bat
scripts/build-windows-release.ps1
scripts/start-water-plant.bat
scripts/README-windows-release.txt
```

## 快速判断

- 本地开发：使用 `python backend/run.py` 和 `npm run dev`
- 本机发给别人运行：使用 Windows 发布包
- 云服务器部署：优先 Docker Compose
- LLM 异常：先检查 `.env` 里的 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`
