# 数据持久化说明

本文说明当前项目中后台配置、运行过程日志和审计日志的持久化位置、职责边界，以及后续迁移到真实数据库时的建议路径。

## 当前结论

后台配置、运行过程日志和审计日志仍采用文件持久化：

```text
backend/data/admin_config.json
backend/data/scenario_logs.jsonl
backend/data/audit_logs.jsonl
```

RAG 知识检索链路已经使用独立持久化服务：

```text
PostgreSQL: rag_documents / rag_chunks / rag_index_runs / rag_index_errors
Elasticsearch: water_plant_rag_chunks
Qdrant: water_plant_rag_chunks
```

本地 Docker 数据目录默认挂载到项目外，例如：

```text
E:\迎风聚智\docker-data\water_plant\postgres\data
E:\迎风聚智\docker-data\water_plant\elasticsearch\data
E:\迎风聚智\docker-data\water_plant\qdrant\storage
```

对应的读写逻辑位于：

```text
backend/app/repositories/admin_config_repository.py
backend/app/repositories/runtime_log_repository.py
```

注意：`repositories/*.py` 是程序代码，不是持久化数据文件。真正保存数据的是 `backend/data` 目录下的 `.json` 和 `.jsonl` 文件。

RAG 检索日志如配置 `RAG_RETRIEVAL_LOG_PATH`，默认可写入：

```text
backend/data/rag_logs/retrieval.jsonl
```

## 文件职责

### `backend/data/admin_config.json`

后台当前配置文件。

包含：

- Agent 配置。
- 方案操作库。

不包含：

- AI 分析历史。
- 沙箱推演历史。
- 人工确认历史。
- 运行过程日志。
- 审计日志。
- 3D 场景资产。
- 动画流程。

读写逻辑：

```text
backend/app/repositories/admin_config_repository.py
```

使用方式：

- 系统首次读取时，如果该文件不存在，则从默认配置源生成。
- GET 接口从内存缓存返回。
- POST/PUT/DELETE 修改内存缓存后写回该文件。
- 服务重启后继续读取该文件，不自动恢复默认配置。

### `backend/app/data/default_admin_config.py`

出厂默认配置源。

用途：

- 首次缺失 `admin_config.json` 时初始化配置。
- 调用系统重置接口时恢复出厂默认配置。

它不是日常运行配置文件，不应在每次启动时覆盖 `admin_config.json`。

### `backend/data/scenario_logs.jsonl`

异常处置运行过程日志。

当前记录的事件包括：

- `scenario_started`
- `supervisor_analysis`
- `agent_analysis`
- `sandbox_result`
- `sandbox_error`
- `human_confirmation`
- `human_rejection`
- `scenario_closed`

AI thinking、沙箱推演结果、人工确认和人工驳回都属于运行过程数据，应进入该文件，而不是进入 `admin_config.json`。

### `backend/data/audit_logs.jsonl`

后台配置修改审计日志。

当前记录的事件包括：

- `admin_agent_updated`
- `admin_plan_action_created`
- `admin_plan_action_updated`
- `admin_plan_action_deleted`
- `admin_config_reset`

该文件用于追踪后台配置被如何修改，不与运行过程日志混放。

## RAG 索引持久化

### PostgreSQL RAG 状态库

默认连接：

```text
RAG_DATABASE_URL=postgresql://water_plant:change-me@127.0.0.1:5432/water_plant
```

容器内连接：

```text
RAG_DATABASE_URL=postgresql://water_plant:change-me@postgres:5432/water_plant
```

职责：

- 保存 Wiki 文档版本、source hash、ACL hash 和索引状态。
- 保存 chunk_id、doc_version、content_hash 和 payload 快照。
- 保存索引运行记录和错误记录。
- 作为 ES/Qdrant 的同步对账基准。

### Elasticsearch BM25 索引

默认 index：

```text
RAG_ELASTICSEARCH_INDEX=water_plant_rag_chunks
```

职责：

- 保存与 Qdrant 同源的 chunk payload。
- 承担关键词/BM25 召回。
- 支持 `status`、`visibility`、`acl.tenant`、`acl.roles`、工艺区域、设备、事件类型等预过滤。

### Qdrant 向量索引

默认 collection：

```text
RAG_QDRANT_COLLECTION=water_plant_rag_chunks
```

职责：

- 保存与 ES 同源的 chunk payload 和 embedding vector。
- 承担语义向量召回。
- 与 ES 一起进入 Hybrid RRF 融合。

### 一致性检查

使用同步脚本检查 Wiki manifest、PostgreSQL、Elasticsearch 和 Qdrant 是否一致：

```powershell
python scripts/sync-rag-indexes.py --check --json
```

只检查 Wiki 和 SQL 状态：

```powershell
python scripts/sync-rag-indexes.py --check --state-only --json
```

## JSONL 格式说明

日志文件使用 JSONL，即一行一条 JSON 记录。

选择 JSONL 的原因：

- 适合日志追加写入。
- 不需要每次写入都重写整个 JSON 数组。
- 单条记录损坏时影响范围更小。
- 后续迁移数据库时可以逐行导入。

示例：

```json
{"id":"log-xxx","timestamp":"2026-06-21T15:30:00+08:00","scenarioId":"hist_1_123","type":"sandbox_result","agentId":"uf","incidentType":"uf_clogging","phase":"sandbox","summary":"沙箱推演通过","payload":{}}
```

## 当前 API

后台配置接口：

```text
GET    /api/admin/agents
PUT    /api/admin/agents/{agent_id}
GET    /api/admin/plan-actions
POST   /api/admin/plan-actions
PUT    /api/admin/plan-actions/{action_id}
DELETE /api/admin/plan-actions/{action_id}
POST   /api/admin/config/reset
```

运行日志接口：

```text
POST /api/logs/scenario
```

## 后续数据库迁移建议

迁移数据库时，优先替换 repository 内部实现，尽量不改 API 和前端调用。

建议映射：

```text
backend/data/admin_config.json
  -> admin_agents
  -> admin_plan_actions

backend/data/scenario_logs.jsonl
  -> scenario_events 或 scenario_logs

backend/data/audit_logs.jsonl
  -> audit_logs

backend/app/data/default_admin_config.py
  -> seed 数据或初始化脚本
```

建议表：

- `admin_agents`
- `admin_plan_actions`
- `scenario_events`
- `audit_logs`

迁移原则：

- 配置数据、运行过程日志、审计日志继续分离。
- `admin_config.json` 的职责只对应后台当前配置。
- AI 分析、沙箱推演、人工确认历史归入运行过程日志。
- 后台配置修改历史归入审计日志。
- 前端优先继续调用现有 API，由后端 repository 层完成存储实现切换。
